# データガバナンス & セキュリティ設計書

## 1. 目的

CRMデータは顧客の購買行動・個人情報を含む機密性の高いデータです。
本設計書は、本番運用に向けたデータガバナンスとセキュリティの方針を定義します。

---

## 2. データ分類

| 分類 | 定義 | 例 | 取り扱い |
|------|------|-----|---------|
| **PII (個人識別情報)** | 個人を直接特定できる情報 | 氏名, メールアドレス, 電話番号 | 不可逆ハッシュ化 or 削除。分析環境には持ち込まない |
| **準PII** | 組み合わせで個人を特定できる情報 | 年齢 + 地域 + 性別 | アクセス制御あり。集計レベルでの利用を推奨 |
| **行動データ** | 個人の行動記録 | 購入履歴, ログイン履歴 | customer_hash経由で参照。生IDでの分析は禁止 |
| **集計データ** | セグメント単位の統計値 | セグメント別平均LTV | 制限なし |

---

## 3. PII管理ポリシー

### 3-1. 現在の実装（維持すべき点）
- メールアドレス → SHA-256ハッシュ化（不可逆）✅
- 氏名カラム → 削除 ✅

### 3-2. 本番で追加すべき対策

| 対策 | 実装方法 | 優先度 |
|------|---------|--------|
| **customer_id の匿名化** | 分析環境では `customer_hash` のみ使用。生IDは本番DBにのみ保持 | P0 |
| **カラムレベル暗号化** | BigQuery のカラムレベルセキュリティ (Column-Level Security) を適用 | P1 |
| **アクセス制御** | GCP IAM でロール別権限を設定（下記参照） | P0 |
| **データマスキング** | 開発環境にはマスキング済みデータのみデプロイ | P1 |
| **監査ログ** | BigQuery の INFORMATION_SCHEMA.JOBS で全クエリを記録 | P0 |

### 3-3. ロール別アクセス権限

| ロール | 生PII | ハッシュ済みデータ | セグメント集計 | モデル | 設定変更 |
|--------|-------|------------------|---------------|--------|---------|
| データサイエンティスト | ❌ | ✅ 読取 | ✅ | ✅ 読書 | ❌ |
| CRMマーケター | ❌ | ❌ | ✅ | ❌ | ❌ |
| エンジニア (MLOps) | ❌ | ✅ 読取 | ✅ | ✅ 読書 | ✅ |
| 管理者 | ✅ (監査時のみ) | ✅ | ✅ | ✅ | ✅ |

## 4. 個人情報保護法への準拠

### 4-1. 利用目的の明示
- 顧客に対し「マーケティング施策の最適化」を利用目的として通知
- プライバシーポリシーに機械学習による分析を明記

### 4-2. 第三者提供の制限
- セグメントラベル・スコアリング結果を外部MAツールに連携する場合は、
  業務委託契約 + データ処理契約 (DPA) を締結

### 4-3. 忘れられる権利（データ削除要求）
```python
# 実装パターン
def delete_customer_data(customer_id: str):
    """
    顧客の全データを削除する。
    1. BigQuery の全テーブルから customer_hash でフィルタして DELETE
    2. GCS の Parquet ファイルは再書き出し（該当行を除外）
    3. 学習済みモデルには個人データが含まれないため、削除不要
       ただし、モデルの再学習時に該当データを除外するフラグを立てる
    4. 監査ログに削除実行記録を残す
    """
```

### 4-4. データ保持期間
| データ種別 | 保持期間 | 根拠 |
|-----------|---------|------|
| 生PII | 利用目的達成後、速やかに削除 | 個人情報保護法 |
| ハッシュ済み行動データ | 3年間 | 分析精度の維持に必要な期間 |
| セグメント集計データ | 無期限 | 個人を特定できないため |
| モデル成果物 | 無期限 (バージョン管理) | 個人データを含まないため |
| パイプライン実行ログ | 1年間 | 運用監査に必要な期間 |

## 5. モデル説明性 (Explainability)

### 5-1. なぜ必要か
- 「なぜこの顧客が離脱リスク高と判定されたか」を説明できる必要がある
- GDPR Article 22: 自動化された意思決定に対する説明義務

### 5-2. 実装方針
- **SHAP値**の計算を推論パイプラインに組み込む
- 各顧客の予測に対し、上位5つの影響要因を記録

```python
import shap
explainer = shap.TreeExplainer(model_churn)
shap_values = explainer.shap_values(X_customer)
# → "この顧客は login_days_30=0 が最も離脱リスクを高めている"
```

### 5-3. 記録先
- BigQuery テーブル: `crm_analytics.prediction_explanations`
- カラム: customer_hash, run_date, churn_probability, top_feature_1, shap_value_1, ...

## 6. インシデント対応

| インシデント | 検知方法 | 対応 |
|-------------|---------|------|
| PII漏洩 | カラム名にPII候補が含まれていないか定期スキャン | 即時報告、漏洩範囲特定、影響顧客への通知 |
| 不正アクセス | BigQuery監査ログの異常検知 | アカウント停止、ログ調査 |
| モデルバイアス | セグメント別の予測精度モニタリング | 偏りが検出された場合、再学習データを見直し |

## 7. GCP上での実装マッピング

| ガバナンス要件 | GCPサービス |
|---------------|------------|
| アクセス制御 | IAM + BigQuery Column-Level Security |
| 監査ログ | Cloud Audit Logs + BigQuery INFORMATION_SCHEMA |
| 暗号化 (at rest) | デフォルトで有効 (Google管理鍵) |
| 暗号化 (in transit) | TLS 1.3 (デフォルト) |
| データ保持 | BigQuery テーブル有効期限設定 |
| シークレット管理 | Secret Manager (APIキー等) |
